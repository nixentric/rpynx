## Causes

- **Keyboard:** `renpy/display/core.py` `update_text_rect()` starts the screen keyboard again
  whenever `has_screen_keyboard_support()` and not `is_screen_keyboard_shown()`. That is
  meant for Android. On the Switch the keyboard is a blocking applet, so it is never "shown"
  when Ren'Py checks, and it reopens on every redraw.
  - Also, A cannot submit a Ren'Py input: `input_enter` is `K_RETURN` / `K_KP_ENTER` only,
    while `pad_a_press` maps to dismiss / button_select.
- **Menu focus:** Ren'Py focuses a button at the start only through `default_focus`, and only
  after keyboard or pad input. With nothing focused, the first D-pad press is spent on
  `focus_extreme`.

## Fixes for run 15 (runtime `16cf8886…`, pushed and verified over FTP; superseded below)

- `rsl_bridge._install_text_input()`:
  - `has_screen_keyboard_support()` reports False, so the keyboard opens once per text field;
  - after Submit, the typed text replaces the field's text;
  - after Submit or Close, Enter is posted, so the field finishes (Close keeps the text).
- `rsl_bridge._focus_main_menu()`: when the `main_menu` screen appears with nothing focused,
  and the virtual cursor is not in use, it does what the first D-pad press would
  (`focus_extreme(0, -1, 0, 0)`).

## Run 15 (runtime `16cf8886…`): name skipped, keyboard left open, wrong menu button

Evidence: user photo of the keyboard over the outfit screen; Album screenshots 04:07 (main
menu) and 04:09 (the name card shows the default "Arlian").

- **Keyboard.** devkitPro SDL 2.28 (`src/video/switch/SDL_switchswkb.c`) uses the **inline**

  - `SWITCH_StartTextInput` makes it appear and returns at once;
  - Submit sends the whole text as one `TEXTINPUT`, with no Enter, then closes it;
  - Close just closes it;

  The run 14 fix pressed Enter right after opening it, which skipped the name, and the
  keyboard could stay on the next screen.
- **Main menu.** Ren'Py's first-press choice is by position: the top bar's "Download …"
  link, not New Game.
- **Cursor.** It sat in the top-left corner from the start, which was confusing.

### Fixes for run 16 (runtime `e03391ac…`, pushed and verified over FTP)

- Keyboard session:
  - the keyboard opens once per text field;
  - while it is open, its `TEXTINPUT` replaces the content of the field last drawn as
    editable (tracked from `Input.render`, because `renpy.input()`'s field has no value);
  - when it has closed, Enter is posted only if a field is still editable and finishes on
    Enter (an action, no value, or a returnable value).

- Cursor: `interface.hide_mouse()` at start and on every pad press; it shows again when the

## Run 18 (runtime `4422e1bf…`): A sometimes pressed the quick menu's "Back"

Evidence: `logs/forbidden-fantasy/python.txt`, 73 A presses logged by the diagnostic.

- Cards and choices worked: the focused `Button`s had the `[Function, Show, Hide]` actions.
- 5 presses hit `Button <Rollback>` (the quick menu's "Back"), with screens
  `('debug_screen', 'quick_menu', 'say')` or `(…, 'skins_menu_b')`.
- Cause: Forbidden Fantasy keeps a buttonless `debug_screen` up at all times. Because it was
  not on the "always up" name list, the first-button rule took the scene for content and
  selected the first button in display order: the quick menu's Back. That focus then
  carried into the dialogue.
