## Fixes for run 8 (loader `b6997861…`, runtime `1dce359e…`, both pushed and verified over FTP)

- **No stack dumps in game mode.** Script mode keeps them; the self-test finishes in 2 s,
  so a dump there only happens when Python is really stuck.
- **Heap audit** (`app/diagnostics/procinfo.c`) at runtime exit and at loader start:
  - sums heap pages that are borrowed (mapped thread stacks), device-mapped (GPU) or
    permission-locked;
  - resets "uncached" pages left by GPU buffers;
  - lists the threads still alive when the syscall is available.

  It shows whether the same-process relaunch crash comes from leaked thread stacks or GPU
  memory, and repairs the GPU case.

## Ren'Py's own threads

Ren'Py joins its audio, preloader and save-scan threads on a normal quit (`bootstrap`
`finally`, `main.py`), so leftover Python threads are a less likely cause.
