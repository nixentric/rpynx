## Bugs found

1. **Labels are cut off instead of wrapping**, in two places:
   - how to play (01:01:29): "Advance the story, choos…", in a row 360 px wide whose text label
     had no width of its own;
   - the Use this screenshot panel (01:03:48): "The framed part, in the library and on the…" and
     "Cover and background from this screensho…", the side menu's subtitles, same cause.

   Both labels were content-width inside a fixed-width parent, so the parent clipped them.
   Nothing checked for it, and on screen it passed for a tight margin: with the host font the
   panel's subtitle already ran 21 px past its parent, and the help row only overflows with a
   font wider than Arial Unicode.

   Fixed in `ui_pages.c` (the row's text now takes the rest of the row and the row is 380 px)
   and `ui_library.c` (the subtitle is full width, so it wraps). `tests/ui/mockups.c` now fails
   when a wrapping label runs past its parent: against the old code it reports 2 labels with the
   host font and 8 with Verdana, which is wider than the console's font; with the fix both fonts
   are clean. Not yet seen on the console.

   Confirmed on the console in the second session below.

   Two things that look like the same bug are not: the details page's performance notes
   (01:02:46) and the second how-to-play card are cut by the bottom of a scrolling area, and
   Diagnostics' recent log is `LV_LABEL_LONG_MODE_CLIP` on purpose.
2. **First frame 130–132 ms**, against 80 ms in the first LVGL test on 2026-10-22. It is the
   same on all three starts, with and without the how to play screen, so it is not noise.

   Measured on 2026-10-23 with a line per start-up stage (loader `57cfdaeb…`, 4 games):
   services 24-57 ms, settings 4 ms, library scan 29 ms (about 7 ms a game), display 3 ms,
   fonts and `ui_init` 1 ms — 61-94 ms in all. The rest is the first frame itself: **build
   152 ms, draw 14 ms**, for 260 ms from `main()`. So it is neither the SD scan nor the
   drawing: it is `ui_update()` building the first screen's objects. [Likely] the console's
   font is parsed and measured there, since `ui_init` loads it in 1 ms and only the first
   text layout touches it.

## What the run led to

Scrolling in Cinematic and moving in and out of the details felt heavy, and the 60 s lines show
why: a full-screen frame is 22-35 ms against 11-17 ms for an ordinary one, and both the fade
between screens and the focus transition animate over the full-screen picture. Raising the
backdrop's settle time changed nothing, which ruled the bake out. The user then dropped the
Cinematic layout and every picture behind the UI; the Row layout took Cinematic's shape, so the
library has Row and Grid, and the importer and *Change picture* make only a cover.
