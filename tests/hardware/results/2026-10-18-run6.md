## Cause and fix (runtime `b23a278b…`, pushed and verified over FTP)

- The quit freeze is in `SDL_Quit()`, the only call between "Ren'Py finished" and "return to"
  in `runtime/main.c`. It was called from the main thread, while SDL, EGL and Mesa had been
  set up on the Python thread.
- Fix: SDL is now shut down on the Python thread after `Py_FinalizeEx`, one subsystem at a
  time, with each step logged. If it still hangs, the log names the subsystem.

## Heat: measure before optimising

- **Telemetry:** every 30 s of play, `runtime.log` gets the SoC and board temperatures (ts
  service), how busy the runtime's CPU core is (idle ticks), battery %, whether it is
  charging, and docked/handheld.
- **Facts from the source:** Ren'Py's `gl_powersave` is already on. While idle it blocks
  and redraws at most once every 0.2 s; during animations it renders at 60 fps (vsync).
- **Opt-in 30 fps cap:** the file `sdmc:/switch/renpy-loader/config/power-saver` sets
  `RENPY_GL_VSYNC=2`, so 30 fps and 60 fps sessions can be compared.
