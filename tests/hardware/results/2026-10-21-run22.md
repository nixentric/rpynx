## Crash

- The first game quit with status 0, but `runtime.log` says `thread still running at exit: entry +0x8ae0d0`
  (`threads: 11 closed, 1 still running`).
- The loader then counted 2 threads instead of 1, and `borrowed` grew from 8592 to 8724 KiB.
- The second launch crashed with a Data Abort (result 2168-0002). The ELF was rebuilt from
  the committed source; the entry resolves exactly to SDL's `RunThread`, which shows it matches.

```
PC armDCacheFlush_L0   libnx arm/cache.s:30
   nvMapCreate         libnx nvidia/map.c:60
   nouveau_bo_new      libdrm_nouveau nouveau.c:387
   nvc0_miptree_create / st_texture_create / st_TexImage / _mesa_TexImage2D
```

- [Likely] The cause:
  - An SDL thread from the first game never finished, so its stack stayed mapped.
  - The pages the stack came from in the heap stay locked.
  - The next runtime's fresh malloc handed those pages to a new GPU buffer, and the cache
    flush over them faulted.
  - This is the same mechanism as the run 11 crash in `memset`. It is a thread that is still
    running, not one that exited without being closed.
- [Guessing] The thread is a Ren'Py media decode thread (music was playing), stuck after
  Python shut down.
