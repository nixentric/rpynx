## Found, and changed after the run

1. **Notice.** On the first build the only sign that a game had arrived was "…, received" in
   small type, overwritten by the next upload; the user could not tell it had worked. The
   second build adds the green notice with the game's title (above). It is what this run tested.
2. **curl and `scripts/switch-ftp.sh`** give paths relative to the login folder. The first build
   started clients in the jail, so curl would have made `switch/renpy-loader/switch/renpy-loader/`.
   The second build starts them at `/`, as sphaira does; `/` and `/switch` list only the way
   down. Host test added (`test_curl_as_switch_ftp_sh_uses_it`).
3. **The speed in the log was wrong.** "104.9 MB in 82 s (1.3 MB/s)" divided by the whole
   connection, which also held a 42 s download. After the run: the server counts the time
   spent receiving, and the line reads `sent N file(s), X MB in Y s (Z MB/s; W MB/s while
   receiving)`; connections that sent nothing are no longer logged. Not on hardware yet.
4. **The card ran into the footer** with the console's wider font once the notice showed. After
   the run the instructions hide while the notice shows. Not on hardware yet (mockup `14b`).
5. `logs/loader.log` cannot be read over the loader's own server while the loader runs: even
   `stat` fails on a file it holds open. A limit of the Switch's file system; the log is read
   over sphaira afterwards.

6. **A pop-up as well**, at the user's request after seeing the note: "<title> arrived" over
   the page, with *Send another game* and *Go to the library*. The applet-mode notice and it
   share the dialog code, now with up to two buttons.

The final build, `27fd355e…`, carries 3, 4 and 6 and is on the SD card, untested.
